# 使用指南

给用这个 skill 的人看的速查。你不需要懂 PPT 怎么生成——你只需要回答几个问题，
然后看结果。

---

## 一句话

把**论文 / 专著 / 报告 / 扫描书**变成一份**每页都有真实截图和完整引注**的汇报 PPT，
并且在动手之前先问你清楚。

---

## 0. 你需要准备什么

| 准备 | 说明 |
|---|---|
| **源材料** | PDF、DOCX，或扫描件都行。扫描件也能做（自动 OCR）。 |
| **大致想法** | 想讲什么。不必想清楚——它会问。 |
| **一点时间** | 全程你会收到 1–2 组问题，答完就不用管了。 |

不需要：安装 Office 插件、准备模板、懂排版。

---

## 五步流程

```
① 你说：材料在哪 + 要什么
        ↓
② 它问你 4 件事（必答）+ 几件可默认的
        ↓
③ 它给你看 7 张样式样张，你挑一个
        ↓
④ 它读材料、定位段落、裁出带高亮的截图、搭好版
        ↓
⑤ 它自己查两轮错（机械门禁 + 一个没参与写作的审阅者）
        ↓
   交付：PPTX + 一份「我替你做了什么 / 我假设了什么」的清单
```

### ① 启动

告诉它**材料在哪**和**你要什么**。最省事的一句：

```
用 build-academic-ppt 把 ~/Documents/paper.pdf 和 notes.docx 做成一页 20 页的中文汇报 PPT。
```

### ② 它问你

必答四项（不答它做不了）：

1. **主题**——这次要讲什么？一句话说清中心命题最好。
2. **核心要点**——最想让人记住的 3–5 条。
3. **研究问题**——这份材料回答的是什么问题？
4. **源材料**——用哪些文件。

可默认的（不答就用默认值）：风格、篇幅、听众、场合、语言、引注格式。

**它会先读你的材料**。材料里已经写明研究问题的话，它不会重复问，而是把抽到的
那条**拿回来让你确认**：「材料里的研究问题是「……」，对吗？」

**只问一轮**（如果你不答，它会再问一次；两轮都没答，它就从材料里推导，
并在交付时列成「假设」让你核对）。

### ③ 选风格

它会给你看 7 张样张：

| 风格 | 像什么 |
|---|---|
| `paper-warm` 暖纸朱砂 | 一本学术专著（默认，最稳） |
| `minimal-white` 极简白 | 极干净，白底细线，内容自己说话 |
| `journal-serif` 学术期刊 | 像期刊文章被拆成幻灯片 |
| `slate-dark` 冷灰深色 | 深色投影，会议室里看得清 |
| `blueprint` 蓝图理性 | 技术文档，流程与阶段 |
| `kraft` 牛皮纸 | 旧书、档案、版本研究 |
| `ink-wash` 水墨留白 | 安静、留白多，适合细读 |

不知道就选**暖纸朱砂**。

### ④ 它干活

- 逐页读源材料，为每一页**找出能支撑这一页论断的那句话**
- 把那句话连同上下文**裁成图并高亮**
- 按你的要点排成 20 页左右（**内容多就合并，不靠加页凑数**）
- 每页配完整引注：作者、年份、篇名、期刊、卷期、页码、DOI

### ⑤ 它自查两轮

- **机械门禁**：查文字压图、文字溢出框、页边越界、字号不足、缺截图、缺引注、
  截图条高低不齐、图注贴住图框
- **一个没参与写作的审阅者**：看渲染出来的图，找人眼能看出而机器查不出的毛病

两轮都过了才交给你。

## 一个完整的示例

**你：**

```
用 build-academic-ppt 把 ~/Documents/paper.pdf 和 notes.docx 做成 20 页中文汇报 PPT。
```

**它：**

```
我先读材料，然后问你四件事：
1. 主题 / 中心命题
2. 核心要点（3–5 条）
3. 研究问题
4. 用哪些文件
另外风格、篇幅、听众、场合、语言、引注格式可以按默认走。
```

**你：**

```
主题：城市更新的三种解释框架。
要点：一是研究问题，二是六条路径各自的依据与方法，三是各路径的证据强度，四是方法边界。
研究问题：译文在哪些可指认的语言层级与原文发生偏移？这些偏移造成什么效果？
风格用暖纸朱砂，20 页，听众是同门研究生，引注用 GB/T 7714。
```

**它：** 开始读、裁图、搭版、跑门禁……最后交给你 PPTX，加一份说明。

## 交付物

| 文件 | 是什么 |
|---|---|
| `*.pptx` | 成品，可直接放映 |
| `*.manifest.json` | 每页的引注与截图清单（工具读，你一般不用管） |
| 交付说明里的「假设清单」 | **它替你决定了什么**——重点看这一节 |

---

## 改一份已有的 PPT（重要）

如果那份 PPT **你手改过**，它默认走「编辑模式」：

```
用 build-academic-ppt 修改 ~/Documents/deck.pptx。
那个文件我手改过，不要重新生成，要在我的版本上改。
```

它会先比对文件时间和大小，判断你有没有改过，然后**在你的版本上改**，
不会重新生成覆盖你的编辑。**它不会不问就动手**——先说要改哪几页。

## 常见情况

**我不想答问题。**
说「不用问，按材料自己定，把假设列出来」——它会问一轮，你答「随便」，它就自己定，
并在交付时列出所有假设。

**风格不满意。**
「换成 `minimal-white` 重做」——它会重排版式，文字和截图照旧。

**页数不对。**
「压到 15 页」/「拆到 25 页」。它按**合并要点**处理，不会靠缩小字号凑页数。

**截图不清楚 / 截到一半。**
「第 7 页的截图换成 P94 那段完整的话」——它会重新定位。

**引注格式不对。**
「引注改成 Chicago 注释体」。

**它把我的文件改了。**
不该发生。如果发生了，指出页码，它会按备份回退——每次安装和编辑都留时间戳备份。

## 手动命令（一般用不上）

```bash
cd <skill>/scripts

python3 brief.py questions      # 打印这轮要问的问题
python3 brief.py status         # 还缺什么
python3 brief.py check          # 闸门：齐了才退出 0
python3 brief.py summary        # 简报全文 + 假设清单

python3 selftest.py             # 自检（31 项）
python3 qa_deck.py deck.pptx    # 只想复查成品时，自己跑一遍机械门禁
```

### 不想重启 agent？

skill 目录是**会话启动时**扫描的，刚装上的 skill 在当前会话可能还没进列表。
两个办法：

- **重开一个会话**，然后直接说「用 build-academic-ppt ……」
- 或者当场让 agent 读文件照着做：

```
读 ~/.claude/skills/build-academic-ppt/SKILL.md 并严格照它执行。
现在用 build-academic-ppt 把我的论文 PDF 做成 20 页中文汇报 PPT。
```

## 硬规矩（它不会违反）

- 正文 **≥ 14pt**。放不下就**加页或合并**，不缩字号。
- 每页内容页**都要有真实截图和完整引注**。
- **没有把握的引文不写**；找不到出处就标出来问你。
- 英文概念给**中文括注**（主成分分析（PCA））。
- 强调用**加粗**，不用「」。
- 不写「两套模型」这种只给数量不给内容的概括。
- **不用你自己改过的文件当草稿重新生成。**
